## ترجمة المبادئ إلى تجربة النظام

- **مسارات مألوفة للمحاسب الفلسطيني:** المستند التشغيلي يقود إلى أثره المالي والمخزني؛ لا نكرر إدخال الفاتورة في الأستاذ.
- **سرعة المحل:** شاشة بيع تضع البحث/الباركود، الأصناف، المستودع، الزبون، السلة، وطريقة الدفع في مساحة واحدة.
- **تمييز المستندات:** الفاتورة، سند القبض/الصرف، مردود البيع، وإرسال/استلام المخزون مستندات مستقلة قابلة للتتبع، وليست تعديلات صامتة على الرصيد.
- **دقة العهدة:** فتح وإغلاق الوردية، رصيد متوقع/فعلي، وفروقات الصندوق قبل اعتماد الإقفال.
- **مراعاة أدوات السوق:** تجهيز واجهات للباركود، اختصارات لوحة المفاتيح، الطابعة الحرارية، الشيك، والعملات؛ لا ندّعي أن التكامل العتادي أو أسعار الصرف أصبح موصولًا قبل تنفيذه واختباره.
- **تخصيص قابل للضبط:** قوالب المستندات والتقارير، ترتيب الحقول، الفلاتر، وصلاحيات بحسب الدور دون تغيير دفتر الأستاذ أو قواعد الترحيل.
- **الشكل محدث لا منسوخ:** استخدمنا تنظيمًا عربيًا RTL وبيانات كثيفة قابلة للمسح البصري، مع مساحات وبطاقات حديثة؛ لم ننسخ أصول الشامل البصرية أو علامته.

## الحالة البرمجية الحالية

أضيفت شاشة نقطة بيع تجريبية إلى واجهة النظام: اختيار المستودع والعميل، بحث أصناف، سلة وتعديل كمية، ضريبة، واختيار وسيلة الدفع. الشاشة حاليًا **معاينة تفاعلية فقط**؛ لا تحفظ الفاتورة ولا تثبت قبضًا/شيكًا ولا تغلق عهدة. يجب تنفيذ API ومعاملات قاعدة البيانات وسجل التدقيق قبل استخدامها تشغيليًا.

## الترتيب المقترح للتنفيذ

1. تعريف الصنف والوحدة والباركود والأسعار/المستودعات.
2. جلسة نقطة البيع وعهدة الصندوق، مع تدقيق الفتح والإغلاق وفروقات النقد.
3. حفظ الفاتورة وبنودها، حركة المخزون، القيد المتوازن، والذمم داخل معاملة قاعدة بيانات واحدة.
4. سندات قبض/صرف تدعم النقد والشيك والبطاقة، مع حالات تحصيل الشيك.
5. مردودات المبيعات والإشعارات الدائنة بالعكس المحاسبي لا بالحذف.
6. قوالب طباعة حرارية/ورقية وفلاتر وتقارير حسب الفرع والمستودع والمستخدم.
7. تفعيل العملات الإضافية فقط بعد تعريف سعر صرف مؤرخ وسياسة فروق العملة.

لا تُعد الشاشة أو البيانات التجريبية نظامًا محاسبيًا جاهزًا للإنتاج.
